# 智能穿戴巡检工作台

面向领导的当前进度说明见 [LEADERSHIP_STATUS.md](LEADERSHIP_STATUS.md)。

可在一台电脑浏览器操作的中文巡检 Demo：管理人员下发预编排任务，执行人在眼镜模拟区逐步核对设备、采集照片、填写结果，完成后生成巡检报告。管理区、执行区和记录区共享同一份任务状态。

本目录同时保留原始任务包（`AGENTS.md`、`SPEC.md`、`ACCEPTANCE.md`、`PROMPTS.md`、`REFERENCE_NOTES.md` 和 `seed/`）。实际实施与检查记录见 [EXECUTION_PLAN.md](EXECUTION_PLAN.md)，汇报操作见 [DEMO_SCRIPT.md](DEMO_SCRIPT.md)。

## 安装与启动

建议使用 Node.js 22 LTS 与 npm；开发环境为 Node.js 22.22.0、npm 10.9.4。推荐新版 Chrome 或 Edge。首次安装依赖及 Playwright 浏览器需要网络。

```bash
cd /Users/mao/projects/inspection-demo
npm ci
npm run demo
```

浏览器固定打开 **http://127.0.0.1:5173**。`npm run demo` 先构建，再启动构建产物预览；终端保持运行，按 Ctrl+C 结束。开发时使用：

```bash
npm run dev
```

开发与演示都绑定 `127.0.0.1:5173` 并启用 `strictPort`。两种服务不能同时占用端口；切换前先停止已有服务。端口被其他进程占用时会明确失败，不会自动换端口。请保持相同浏览器、用户配置及地址；改用 `localhost`、其他端口、其他浏览器或隐私窗口，会进入另一份浏览器存储。

依赖安装后，页面、字体、图标和演示素材均来自本机；核心流程不依赖公网、后端、云账号、API Key 或模型服务。

## 可以演示的功能

- **任务下发与接收**：选择模板、设备和执行人，点击“下发任务”；眼镜显示“收到任务”，点击“开始巡检”。同一时间最多一个未完成任务。
- **Rokid 任务桥接**：任务下发后可在管理区导出 `Android task.dispatch` JSON，导入手机端后由 Room 保存并下发 Glass3；它与历史报告 JSON 分开。
- **五步主线**：确认巡检设备 → 检查柜门与外观 → 检查设备指示灯 → 检查控制面板 → 提交巡检记录。设备可手工输入资产码或“模拟扫描当前设备”。
- **现场留证**：“采集照片”提供“使用演示图片”“选择本地图片”“开启摄像头”。支持 JPEG、PNG、WebP，单张上限 10MB，校验真实格式与可解码性。当前步照片可删除、重新采集或打开大图；完成步骤只读。
- **完整性检查**：“完成本步”会列出缺少的照片、结果、异常说明或确认。异常登记齐全后可继续，报告分别显示任务“已完成”和检查结论“发现异常”。
- **保存与恢复**：草稿自动保存；“暂停巡检”保存当前资料，再次打开同一地址可“继续巡检”。照片从已保存的 Blob 恢复。
- **模板与历史**：“流程模板”可修改名称、发布版本、各步名称、说明、照片数和结果要求，并增删或调整内部检查项顺序。首末步骤固定，至少保留一个检查项。已下发任务使用模板快照；后续任务使用新版本。“巡检记录”可查看独立的历史任务。
- **报告与重置**：报告包含设备、人员、时间、模板版本、各步照片、结果、异常和操作时间线；支持打印与导出 JSON。“重新演示”经二次确认后恢复默认数据。

## 保存、打印与重置

数据保存在当前 origin 的 IndexedDB 数据库 `wearable-inspection-demo` 中。模板配置、任务、照片 Blob 和事件分别保存；照片写入与步骤关联、步骤完成与操作事件采用事务提交。完成操作携带 `taskId`、`expectedStepId` 和唯一 `commandId`，防止重复推进及旧动作修改新步骤。object URL 仅供当前页面预览，既不持久化也不导出。

完成任务后点击“查看巡检报告”或记录列表的“查看报告”：

1. 点击“打印报告”。应用等待照片加载，再打开浏览器打印界面；选择打印机，或选择“另存为 PDF”。打印版隐藏导航与操作按钮。
2. 点击“导出 JSON”。下载内容包含结构化任务、统计、时间线和照片元信息（来源、尺寸、文件类型等）。**JSON 不包含图片二进制，也不是可直接恢复照片的备份**；需要带图片保存的报告请打印为 PDF。
3. 需要新一轮独立巡检时，返回工作台点击“下发新任务”，历史记录继续保留。
4. 需要清空本次演示时，点击顶部“重新演示”→“确认重置”。“取消”保留数据。确认会清除本应用的任务、图片、事件并恢复默认模板与资产，同时关闭采集预览、释放相机资源。

浏览器清理站点数据会删除本地记录。出现保存失败时页面保持原步骤并提供重试；请检查浏览器可用存储空间或站点存储限制后再试。

## 摄像头与人工补测

“采集照片”弹窗内点击“开启摄像头”后才请求视频权限，不请求麦克风。允许权限后点击“拍照并保存”；拒绝、未连接设备或等待超时时，仍可使用演示素材或上传。关闭预览、退出弹窗或重置会停止媒体 tracks；迟到的授权结果会被释放。

浏览器要求摄像头运行于安全上下文，固定回环地址 `http://127.0.0.1:5173` 可用于本地演示。若系统未授权，在浏览器站点权限及操作系统隐私设置中允许对应浏览器访问相机。不要把页面改为普通局域网 HTTP 地址来测试相机。

**真实摄像头硬件与操作系统权限尚未人工实测。** 自动化使用 Canvas MediaStream 模拟画面、权限拒绝 mock 和媒体 tracks 检查，不能替代真实硬件验收。现场使用前按以下清单补测，并记录浏览器、系统、设备和结果：

| 场景 | 人工操作与预期 | 状态 |
|---|---|---|
| 允许权限与拍照 | 点击“开启摄像头”，允许权限；画面可见；点击“拍照并保存”后缩略图出现，刷新照片仍可见 | 待现场实测 |
| 拒绝权限 | 在首次授权时拒绝；显示说明，改用演示图片或上传可完成当前步 | 待现场实测 |
| 设备缺失或被占用 | 断开摄像头或占用设备；显示错误，替代入口可用 | 待现场实测 |
| 释放硬件 | 开启预览后关闭弹窗；浏览器摄像头占用指示应消失；再次开启、关闭预览再“重新演示”，无遗留占用 | 待现场实测 |
| 迟到授权 | 授权未回应时关闭弹窗，随后允许；不得写入照片或保持相机占用 | 待现场实测 |

## 自动化验证

实际执行结果、失败修复和验收证据统一记录在 [artifacts/verification.md](artifacts/verification.md)。以下为可复现命令，不代表未经执行的检查已经通过：

```bash
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm run test` 为单次执行，不进入 watch。Playwright 自动启动固定地址的开发服务，使用独立浏览器上下文与 fixture 图片，不读取演示人员的浏览器数据；运行前停止占用 5173 的手动开发／演示服务。测试报告在 `playwright-report/`，失败截图与 trace 在 `test-results/`。

从构建产物验证同一套端到端流程：

```bash
DEMO_BUILD=1 npm run test:e2e
```

该命令通过 Playwright 启动 `npm run demo`，仍使用相同 host 和 port。纯函数及仓储单测覆盖状态转换、字段校验、快照、重复／过期命令、事务失败与统计；组件测试覆盖字段错误、预览、弹窗、相机回退及只读报告；端到端测试覆盖五步主线、异常、恢复、上传、模板、报告、多任务及重置。

三种视口（1366×768、1440×900、1920×1080）的五类状态截图保存在 `artifacts/screenshots/`。文件名前缀为视口宽度，例如：

| 文件名后缀 | 状态 |
|---|---|
| `01-initial.png` | 初始工作台 |
| `02-missing-photo.png` | 缺照片提示 |
| `03-running.png` | 第 3 步执行中 |
| `04-paused-restored.png` | 暂停后刷新恢复 |
| `05-completed-report.png` | 完成报告 |

## 源码与后续边界

Android 适配方案见 [ANDROID_ROKID_ADAPTATION.md](ANDROID_ROKID_ADAPTATION.md)，Android 工程入口见 [android/README.md](android/README.md)。当前项目已经把 Web 领域模型映射到版本化协议样例，并提供 Glass3 企业版手机端与眼镜端源码；真实硬件链路仍需要企业 SDK 凭证和调试线。

| 路径 | 职责 |
|---|---|
| `src/app/` | React 共享上下文、初始化与三栏工作台 |
| `src/domain/` | 数据类型、纯状态转换、字段校验与命令守卫 |
| `src/services/` | 命令顺序、业务服务与报告导出 |
| `src/repositories/` | IndexedDB 数据访问及事务边界 |
| `src/features/` | 采集弹窗、图片处理、模板编辑、报告 |
| `src/data/`、`seed/` | 默认模板、设备和人员 |
| `src/styles/` | 工作台布局与视觉样式 |
| `public/demo-media/` | 本地 SVG 示意素材，采集时转成 PNG Blob |
| `tests/unit/`、`tests/e2e/`、`tests/fixtures/` | 单元／组件／端到端测试与上传素材 |
| `artifacts/` | 检查记录与状态截图 |

首版 Web 产品仍是单浏览器本地演示；页面标注“本地演示”“眼镜界面模拟”和“演示素材”，不表示浏览器里的真实硬件在线、后台同步或自动识别。Android 双端源码和验收边界见 `android/`；910B 识别、实际二维码解码、跨网络音视频、企业登录及多用户平台仍未纳入 Web 首版范围。后续可替换 Repository 数据接口，并依据现有步骤定义与命令协议接入终端。

SPEC 中的 P1（语音播报、眼镜独立放大、明确标识的模拟图片核验、摄像头双区域显示）及可选模拟断网队列暂未实施；不影响本次固定巡检、现场记录和报告的主线范围。

## 4号楼真实巡检表演示（2026-11-03）

已加入两份PDF全部10页对应的 **12套流程、30个巡检对象、135个检查项**。左侧“巡检模板”可按电气、暖通分组选择；原机柜五步演示继续保留。

选择模板 → 选择设备/区域 → 填写巡检日期、时段、班次 → 下发 → 核对设备 → 逐项记录状态/实测值 → 提交报告。各表时段、数值阈值、成对读数、原表来源均随模板保存；超限需登记异常和说明，关机/待机/不涉及需注明原因。新增流程照片按需采集。

旧浏览器数据自动补充模板，无需“重新演示”。数值、模式、状态、日期/班次和原表出处会出现在报告与JSON中。当前一次任务覆盖一个对象、一个时段，未实现全天原纸表矩阵汇总或自动派单。完整来源映射、阈值解释及范围见 [BUILDING4_FLOWS.md](BUILDING4_FLOWS.md)。
